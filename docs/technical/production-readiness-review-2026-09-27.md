# Cadrora production review — 2026-09-27

This is a fresh source, test, build, and Cloudflare zone-rule review. It does not certify an undeployed Worker or production D1/R2 data. The local checkout contains the E2E, deletion, diagnostics, pagination, cache, portfolio, and abuse-control changes from this production-preparation effort.

## Verified in this review

- Both `cadrora.com` and `ateliergiulia.com` have an active Cloudflare zone rate rule for POST login, protected-gallery unlock, and face-search paths: 30 requests per IP in 10 seconds, then a 10-second block. The Worker Rate Limiting binding configuration and middleware cover these routes on preview and `workers.dev` after deployment. Turnstile still verifies login and unlock.
- Public and admin pages use shared `Button`, `Input`, `Select`, `Modal`/`ConfirmDialog`, `ProgressivePhoto`, gallery card, and `InfiniteLoadMore` components. The admin gallery list and public gallery pages use the same scroll-triggered load control. Domain-specific editors remain separate.
- Gallery, service, Home introduction, and portfolio photos pass through one browser decoder/orientation/metadata-removal implementation and one verified-upload header contract. Services, Home introduction, and portfolio now share one four-variant upload sequence at 320/640/960/1280 px and quality 0.78. Galleries keep five prepared variants including 3840 px download at quality 0.9, with their separate resumable import journal.
- Gallery deletion fences D1 access and advances through at most 100 D1-derived media/face/metadata items per maintenance claim. Admin diagnostics retain classified Worker 5xx errors for 30 days and provide an owner-triggered, 100-object R2 inventory per namespace. The inventory never deletes untracked objects.
- `npm run check`, `npm run test` (330 tests), `npm run build`, `npm audit --audit-level=high` (0 advisories), and the local Chromium E2E suite (52 passed) passed during this effort. The 14 profile-specific cases skipped in the default run passed separately with `CADRORA_SITE=atelier-giulia`. The E2E suite uses browser network mocks for D1/R2/API scenarios.

## Prioritized remaining work

| Priority | Finding and evidence | Action before or after launch |
| --- | --- | --- |
| **P0 — release gate** | The new Worker bindings, D1 error-log migration, default public-media cache, and admin diagnostics exist in this checkout but have not been deployed or validated against the actual production Worker. The local build warns that `AUTH_PEPPER` is absent from local `.dev.vars`; that warning does not establish production secret state. Local E2E deliberately mocks the provider paths (`e2e-testing.md`). | Rehearse migration and bindings in preview, run the same revision's checks, deploy only when active imports are clear, then verify custom domain, preview, and `workers.dev` auth/429/cache behavior and Cron cleanup. Record exact deployment revision and live responses. |
| **P1 — D1 read budget** | The paginated admin gallery query still performs three correlated photo/variant aggregates for each returned gallery (`src/server/routes/admin/galleries.ts`, `adminEventSelect`). The default 24-gallery page can revisit many D1 rows despite the new order index. | Measure D1 `rows_read` with representative galleries; if material, maintain photo count, retouch count, and bytes as transactional counters or fetch them lazily for visible rows. |
| **P1 — deletion scale** | Deleting a portfolio collection builds one D1 batch with one maintenance job per photo, plus fence/delete statements (`src/server/routes/portfolio.ts`, collection DELETE). The product allows 200 portfolio photos globally. | Apply the same durable bounded-batch approach used for gallery deletion before an owner fills a large collection; rehearse a near-limit deletion with real D1/R2 and an interrupted Cron run. |
| **P1 — production lifecycle** | The 100-object R2 inventory finds R2 objects with no variant row after a 15-minute grace period and displays deletion-job counts. It cannot prove that D1-recorded objects still exist in R2, detect orphan Vectorize entries, or automatically alert on failed jobs (`src/server/services/mediaDiagnostics.ts`). | Run the complete inventory and inspect failed jobs during release/operations. Add a bounded D1-to-R2 existence audit and alerting if production volume warrants it. Do not auto-delete a key merely because one scan flags it. |
| **P1 — real device and recovery** | Face-search inference, camera use, and a genuine interrupted multi-file import are not covered by mocked local E2E (`docs/face-search.md`, `e2e-testing.md`). | Validate on iPhone Safari and a preview Worker with representative originals; verify pause/restart/resume, gallery withdrawal, and physical cleanup. |
| **P2 — portfolio media reads** | Gallery display variants and service images have named edge-cache entrypoints, but `/portfolio-media/:id/:variant` still reads R2 on each uncached Worker request (`src/server/routes/portfolio.ts`). Its URL does not include a revision. | Measure actual R2 class B operations and cache hit rate first. If meaningful, add a portfolio cache behind the current D1 publication check and test unpublish/delete invalidation. |
| **P2 — marketing upload recovery** | The shared marketing upload sequence is consistent, but service/Home/portfolio uploads have no persisted journal or bounded retry like gallery imports (`src/app/admin/uploadMarketingPhoto.ts` versus `src/browser/jobs/ImportApi.ts`). | Add retry for transient upload responses and clear resume/cancel behavior if real owner uploads show failures. Keep the four-variant path simple until then. |
| **P2 — large modules** | Gallery admin routes, import routes, and admin gallery UI each exceed 500 lines. The portfolio viewer reuses `PhotoViewer` with disabled selection handlers (`src/app/public/PortfolioPage.tsx`). | Split by lifecycle or editor boundary when changing these areas; extract a media-only viewer contract if more public image surfaces appear. Avoid a broad rewrite solely for file length. |

The currently active zone WAF rules protect custom-domain traffic, while the pending Worker binding code is needed on preview and `workers.dev`. Cloudflare zone analytics and real R2/D1 usage are required to judge photo cost; source inspection and browser cache headers cannot provide an actual invoice.
