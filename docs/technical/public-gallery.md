# Events and public gallery integration

Package PB remains isolated behind central Worker and SPA registration, without coupling event behavior to either application root.

## Worker integration

- Call `registerPublicRoutes(app, services)` from `src/server/routes/public/index.ts` at the feature-route marker in `src/server/app.ts`.
- Call `registerAdminEventRoutes(app)` from `src/server/routes/admin/galleries.ts` at the same marker.
- Register `ogMetadata` from `src/server/middleware/ogMetadata.ts` before the static asset fallback. It responds only to recognized crawlers on event paths; ordinary SPA navigation continues normally.
- PB applies its cache classification directly and also records `cachePolicy`, because Hono middleware registered after a terminating route cannot post-process that response.
- Supply `issueEventGrant` to `registerPublicRoutes`. The callback must issue PA's signed/opaque grant containing only `eventId` and `accessVersion`. The route fails closed with `503` if no issuer is configured. PA's auth context must verify that grant before exposing it to PB.

## SPA integration

- Import `publicRouteObjects` from `src/app/routes/publicRoutes.tsx` into the root router. Importing the module installs the package-local FR and EN resource bundles and public gallery CSS.
- Configure `configurePublicGallery({ getTurnstileToken })` from `src/app/public/config.ts` with PA's event-unlock Turnstile widget. The default provider returns no token and unlock fails closed.
- The route objects cover `/`, `/e/:slug`, `/e/:slug/photo/:photoId`, `/privacy`, and `/contact`.

## Behavioral contracts

- Slugs are assigned once at creation and cannot be changed by the update schema.
- Published, online public galleries appear in the event list with their authorized public covers only while **Show in public gallery lists** is enabled. The shared photo component displays a public cover's revisioned thumbnail first, then one browser-selected display copy; the card retains its fixed visual height while each copy loads. Published, online protected galleries follow the same switch and appear with their public title, event date, and description over one generic static image; their cover and photos still require a current gallery grant. Public and protected cards are interleaved by gallery creation time, newest first; the displayed card date remains the event date. The locked page reads a separate text-only preview by direct locator, including when its card is hidden from the index, while the protected detail API stays locked before unlock. `unlisted` events work by direct URL and emit `noindex,nofollow` for crawlers and browser metadata. Drafts return `404`. The listing switch never changes direct-link access.
- Gallery details and the first photo page are requested in parallel. Both Worker routes enforce access independently; a newer event revision invalidates a previously loaded photo page before pagination continues.
- Photo cursors encode `sortKey`, `id`, and the event revision. A cursor from an older revision returns `409` instead of skipping or duplicating silently.
- Public event APIs use `public, max-age=60`; protected event APIs and crawler shells use `private, no-store`; admin APIs use `no-store`. Revisioned media classifications remain owned by package PD.
- The gallery uses the shared `ProgressivePhoto` component to render an aspect-ratio-preserving blurred small copy, then one browser-selected display copy near the viewport. While the viewer is open, grid photo images are suspended so hidden mosaic requests do not compete with the selected photo; closing the viewer restores them without changing the grid layout. The viewer uses the same preview and selected-size stages for the selected photo, warms only adjacent slides, and derives its blurred backdrop and thumbnail rail from the smallest prepared copy. The existing cursor API still returns bounded pages, but an intersection sentinel fetches the next page as visitors scroll; the manual button remains as an accessible fallback. The compact gallery header has text and actions only, leaving the cover image on the directory card. The viewer provides Escape, arrow-key, button, and horizontal-swipe navigation. On laptop and desktop viewports it is an almost-full-screen rounded lightbox over a blurred backdrop; touch-sized viewports remain edge-to-edge. Typical landscape photos fill the desktop lightbox with a modest crop; portrait photos and mobile views retain the full image over a blurred, photo-derived backdrop rather than black bars. Shared SVG icon controls remain geometrically centered and hover states must not replace positional transforms. It links downloads only when the gallery permits them and a generated copy exists; a retained original is preferred when enabled.
- The gallery page can span a wider viewport than the static site. Its responsive, variable-height photo mosaic keeps each image's aspect ratio and narrow gutters. Hearts appear on each tile and in the viewer. Private hearts are one shared D1 state visible after another authorized visitor reloads; public hearts are gallery-keyed browser-local state and never call the server write route. Private favorite writes require a same-origin request and current gallery grant. During download selection, the heart is hidden so the tile has one clear action.
- Private-gallery check marks are a second, independent shared state for photos requested for retouching. The owner can close retouch selection in gallery settings; existing choices stay in the admin queue, and the Worker rejects further visitor writes until reopened. The heart remains a favorite. Both controls are hidden during visitor download selection. The gallery header shows its title, date, context, and available browse, find, and download actions before the photo mosaic. The public `/galleries` index makes whole cards clickable; protected cards disclose only event details, use a generic image and lock icon, and never source private gallery media. The mosaic uses at most three desktop columns, two on tablet, and one on phone.
- Visitor download selection is gallery-local and works on loaded photos, including the filtered "Found for me" view. One photo uses the authorized media attachment directly. For multiple photos, `downloadPhotos.ts` streams directly into the selected directory through `showDirectoryPicker` when supported, or lazily constructs a bounded ZIP on the visitor device. Do not set the picker `startIn` to Downloads: Chromium may reject that special folder itself as sensitive. The UI surfaces picker rejection instead of silently swallowing its `AbortError`; ZIP remains the fallback. Repeated saves append a numeric suffix to colliding filenames instead of intentionally overwriting them. Keep picker restrictions and keyboard instructions in operator documentation, not as permanent selection-panel copy. The ZIP accepts at most 100 photos/250 MB, keeps the selection on failure, and offers the finished Blob through a user-clicked link. Every media URL is constrained to the same-origin, exact gallery/photo/revision `download` or `original` route; the Worker rechecks authorization for each request. Keep the folder picker call inside the original click activation.
- In selection mode, all photo tiles become selection controls: photos without a `downloadUrl` are marked unavailable and open an explanation instead of selecting or navigating. Shift-click adds the inclusive range of available photos in the current visible order; the anchor resets on bulk selection/clear/filter departure. Ctrl+A / ⌘A selects all currently visible downloadable photos without hijacking editable inputs. A themed information control explains the available-versus-visible count. Exiting selection mode restores ordinary viewer links.
- Generic `.public-main :where(a:not([class]))` styling applies only to plain text links. The shared `BackLink` component owns the gallery, face-search, and contact return links, including arrow, colour, border, and hover behavior; classed component links must not inherit generic link decoration.
- `showPhotoMetadata` is an event-level owner setting that defaults off. When enabled, the viewer information control reveals only filename, event-local capture date/time (including seconds and timezone), and dimensions already returned by the authorized photo API.
- A successful face search stores only up to the default 2,000-photo event cap as sanitized direct-match and nearby-moment references in event-keyed `sessionStorage`. Nearby context is at most four photos before and four after each match, based only on same-gallery capture instants within five minutes. The gallery exposes an **All photos / Found for me** control, automatically loads paginated results, and renders possible matches and nearby moments in distinct labelled groups. Viewer links preserve whether they originated in the gallery or find page; closing returns to that source. Storage contains no selfie, crop, embedding, similarity score, or vector ID.
